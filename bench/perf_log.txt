Future ideas
------------
1. Reduce Formula_egraph_uf.register_term hashtable traffic. The remaining top
   profile entry is still Base.Hashtbl.add_worker/find_and_call under
   Formula_egraph_uf.register_term, Formula_egraph.add_to_global, and Encoding.
   Next likely wins are interning/caching more compact keys or avoiding duplicate
   id_by_term/term_by_id/node_by_id/global indexes where possible.

2. Replace Formula_egraph_uf Explanation_forest Int.Table add_multi lists with a
   custom vec-backed adjacency structure. BFS/explanation paths create temporary
   Int.Hash_set/Int.Table structures and multi lists; this may matter more on
   explanation-heavy unsat cases.

3. Consider mutable per-class node storage with explicit undo logs. The current
   list-backed persistent Node_index keeps undo simple. A mutable vector/hash-set
   could reduce materialization/set costs further, but only if undo entries record
   each mutation correctly.

4. Add a dedicated quantifier/e-matching benchmark before changing
   nodes_with_op further. Current tests are too small (~0.05s) to catch regressions.

5. Pre-size SAT/theory tables from formula statistics. The fixed 128 sizes help
   EUF, but a first pass over asserted formulas could choose tighter capacities
   for large vs tiny instances.

Kept changes
------------
1. Stop maintaining Node_index.nodes_by_op eagerly.

   Before: per-class Node_index was { nodes : Node.Set.t; nodes_by_op :
   Node.Set.t Op.Map.t }. The by-op map is only needed for e-matching, but EUF
   congruence closure paid to update/merge it on every add/remove/union. Probe
   for EUF chain n=1000 found ~434k words/iter in Node_index ops out of ~712k
   total words: ~216k in nodes set operations and ~258k in nodes_by_op map work.

   Change: Node_index keeps only nodes; nodes_with_op filters on demand.
   Pattern/e-matching tests still pass. A synthetic e-matching stress test also
   got faster rather than slower because it no longer pays eager map maintenance
   during graph construction/merging.

2. Store Node_index.nodes internally as a Node.t list, materializing Node.Set.t
   only at API/query boundaries.

   This preserves the cheap undo story (node indexes remain persistent values on
   the trail) while replacing AVL set union/add/remove on the hot merge path with
   list cons/append/filter. Public Class.nodes still returns Node.Set.t.

3. Avoid allocating canonical nodes when children are already canonical.

   canonical_node' used to always build a replacement node/list and then discard
   it on `Unchanged`. Probe showed this was small (~18k words/iter for EUF chain
   n=1000) but cheap to remove.

4. Pre-size long-lived egraph/UF tables moderately.

   Created Graph tables and Formula_egraph_uf tables with size 128 (or 32 for
   small op/falsehood tables). This reduced hashtable resize work without making
   small cases noticeably worse.

Rejected / reverted attempts
----------------------------
1. Change Node.children from Id.t list to Id.t array.

   This was prompted by the "node unboxing" idea, but measurement showed child
   lists were not the allocation problem: canonical_node' children allocation was
   only ~18k words/iter on EUF chain n=1000. Switching to arrays was essentially
   allocation-neutral (and slightly worse on web before pre-sizing), while it
   exposed mutable arrays inside Node.t, which is used as a hash/set key. Reverted
   to Id.t list.

2. Optimize Ds.Vec.get try/with wrappers.

   Earlier microbenchmark showed only ~3% on a pure inlined get loop and under
   1% overall. Not worth losing the nicer bounds errors right now.
